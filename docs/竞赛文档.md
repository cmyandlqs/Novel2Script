# 赛题三硬约束整理：AI 小说转剧本工具

## 一、赛题基本信息

### 赛题名称

**AI 小说转剧本工具**

### 目标用户

**小说作者**

### 核心痛点

小说作者希望将自己的作品改编成剧本，需要降低改编门槛、提升改编效率。

### 产品定位

开发一款 **AI 辅助剧本创作工具**。

---

# 二、作品功能硬约束

## 1. 输入要求

作品需要支持输入：

> **3 个章节以上的小说文本**

明确约束：

| 项目   | 要求        |
| ---- | --------- |
| 输入内容 | 小说文本      |
| 输入规模 | 3 个章节以上   |
| 输入用途 | 用于自动转换成剧本 |

---

## 2. 输出要求

作品需要输出：

> **结构化剧本**

格式要求：

> **YAML 格式**

明确约束：

| 项目   | 要求         |
| ---- | ---------- |
| 输出内容 | 剧本初稿       |
| 输出形式 | 结构化        |
| 输出格式 | YAML       |
| 输出目标 | 可编辑、可进一步打磨 |

---

## 3. 附加文档要求

除工具本身外，还必须额外提交一篇文档：

> 定义剧本的 YAML Schema

文档中必须说明：

> 该 Schema 的设计原因

明确约束：

| 项目   | 要求             |
| ---- | -------------- |
| 文档内容 | YAML Schema 定义 |
| 必须说明 | Schema 的设计原因   |
| 文档作用 | 解释剧本结构设计       |

---

# 五、无效作品情形

以下情况会导致作品无效或被取消资格。

## 1. 直接视为无效作品

| 情形                       | 结果       |
| ------------------------ | -------- |
| 仅在最后一天一次性导入所有代码          | 直接视为无效作品 |
| commit 时间戳不在所选批次开始与截止时间内 | 视为无效作品   |

---

## 2. 其他无效情形

| 编号 | 情形                                     |
| -- | -------------------------------------- |
| ①  | PR 描述空白，或与实际代码变更严重不符                   |
| ②  | 引用了第三方库或框架，但未在 README 中列明依赖，且未说明原创功能部分 |
| ③  | 复用了自己过去的代码片段，但未在 PR 描述中注明来源            |

## 3. 学术诚信相关处罚

| 技术抄袭          | 取消路演资格，并列入招聘黑名单 |

# 六、PR 提交规范硬约束

5. **输出结果应是可编辑、可进一步打磨的剧本初稿。**
6. **必须额外写 YAML Schema 文档。**
7. **Schema 文档必须说明设计原因。**
8. **必须提交公开 GitHub / Gitee 仓库。**
9. **必须提交 README。**
10. **必须提交可播放 Demo 视频，并把链接放入 README。**
11. **必须持续开发，不能最后一天一次性导入代码。**
12. **所有 commit 时间戳必须在所选批次开始与截止时间内。**
13. **每个 PR 只做一件事。**
14. **PR 标题和描述必须清晰完整。**
15. **PR 描述必须包含功能描述、实现思路、测试方式。**
16. **主分支在每次 PR 合并后都需要保持可运行。**
17. **第三方依赖必须在 README 中列明。**
18. **原创功能部分需要说明。**
19. **复用历史代码必须在 PR 描述中注明来源。**
20. **代码仓库需在开题后创建。**
21. **不得抄袭，不得侵犯知识产权。**
